一、版本背景
--------------------------------------------------------------------
V1.0 已实现：
  · 11 项必要输入，自动推导 Reach / Stack / Wheelbase / Trail 等
  · 最多 3 台车彩色叠画对比 + 数值差表
  · 后轴 / 地面线两种对齐基线
  · 单文件 bike_geo.html，离线可用
  · 模板保存/载入/删除（仅保存在本机浏览器 localStorage）

V1.1 目标：
  · 解决模板无法跨设备、跨浏览器迁移的问题
  · 补充与骑行姿态相关、但非车架几何必需的选装数据
  · 保持单文件、离线、无依赖的交付形态


二、需求 1：模板导出 / 导入（P0，必须）
--------------------------------------------------------------------
问题：
  目前模板保存在浏览器 localStorage 中。换设备、换浏览器、重装系统或清理
  浏览器数据后模板会丢失，只能重新输入。

目标：
  模板可以导出为独立文件保存或转发；在新设备/新浏览器上导入后即可继续使用。

2.1 导出
  · 提供“导出模板”入口（可与现有 Save template / 删除按钮放在同一区域）。
  · 默认导出当前浏览器中的全部模板，生成一个 JSON 文件。
  · 文件名建议：bikegeo-templates-YYYYMMDD.json。
  · 文件内容至少包含：
      版本号（schemaVersion，便于未来兼容）
      导出时间
      模板数组：name、inputs（含现有 11 项输入 + V1.1 选装字段）、presetId
  · 不含任何设备信息、账号信息、绝对路径或网络请求。

2.2 导入
  · 提供“导入模板”入口，通过文件选择器读取上述 JSON（浏览器 FileReader）。
  · 导入校验：
      文件必须是合法 JSON；
      schemaVersion 可识别；
      name 非空，inputs 为对象；
      非法文件给出明确错误提示，不污染现有模板。
  · 同名模板冲突处理：
      默认逐个提示“覆盖 / 保留两者（自动改名，如 xxx (2)）/ 跳过”；
      或提供“全部覆盖 / 全部跳过”选项（最终交互可在实现时定）。
  · 导入完成后刷新模板下拉框，并提示导入数量。

2.3 兼容性
  · 导入的模板应走现有 solve() 的 clamp 逻辑，防止异常数值破坏绘图。
  · 旧版本（V1.0）模板文件也允许导入：缺少的选装字段按“未填写”处理。
  · 导出/导入不改变现有模板的本地保存行为；两者并存。

2.4 验收标准
  · 在 A 浏览器导出 JSON，复制到 B 设备/B 浏览器导入后，模板名称与全部
    输入值一致，载入后绘图与 A 浏览器一致。
  · 导入非法 JSON、空数组、超范围数值、缺失字段时，程序不崩溃且提示清晰。
  · 断网、file:// 直接打开、单文件版场景下均可正常导出/导入。
  · 导出的 JSON 中不包含任何隐私信息。


三、需求 2：新增可选骑行姿态数据（P1，建议）
--------------------------------------------------------------------
问题：
  车架几何之外，牙盘、把立、坐高/座管等装配与设定数据同样影响骑乘结果，
  但目前工具没有这些字段，无法在对比中记录。

目标：
  增加三类“选装数据”，全部为可选（允许留空）；留空时不参与绘图与对比，
  不改变任何现有车架几何计算。

3.1 牙盘（Crankset）
  · Crank length：曲柄长度，单位 mm。
    常用值 160 / 165 / 170 / 172.5 / 175。
  · 可选字段，留空表示未填写。
  · 不参与车架几何推导；可在对比表中单独列出。
  · 若实现绘图，可最小化表示为 BB 处的曲柄/牙盘示意；不要求精确建模。

3.2 把立（Cockpit / Stem）
  · Stem length：把立长度，单位 mm。
  · Stem angle / rise：把立角度或上扬量，单位与定义待确认（见第六节）。
  · Spacer stack（可选）：头管上垫圈总高度，单位 mm。
  · 以上均为可选字段；不参与车架几何推导。
  · 建议由此可推导（非本版必须）把横安装点相对 BB 的坐标，用于姿态对比。

3.3 坐高 / 座管（Saddle / Seatpost）
  · Saddle height：坐垫高度，单位 mm（建议定义：五通中心 → 坐垫顶面；
    具体测量路径待确认，见第六节）。
  · Seatpost offset / setback：座管后飘量或坐垫相对立管轴线的水平偏移，
    单位 mm。
  · Saddle angle（可选）：坐垫角度，单位 °。
  · 均为可选字段；不参与车架几何推导。

3.4 交互与数据规则
  · 新增“Optional fit / 选装数据”区域，与现有 11 项必填输入视觉区分。
  · 可选字段默认为空；空值不显示 0，不参与计算，不进入绘图。
  · 可填写一个或多个字段，互不依赖；输入范围做基本校验。
  · 模板保存/导出需包含已填写的选装字段；留空字段不写入或写为 null。
  · 对比表（Compare）在任意一台车填写了选装字段时显示对应行；
    未填写的车显示“—”。
  · 切换车辆、载入预设、载入模板时，选装字段与车架输入同步切换。
  · 选装字段的变化不得影响 Reach / Stack / Wheelbase / Trail 等结果。

3.5 建议的初始范围（可在实现时调整）
  · Crank length：120 ~ 200 mm
  · Stem length：30 ~ 150 mm
  · Spacer stack：0 ~ 100 mm
  · Saddle height：500 ~ 900 mm
  · Seatpost offset / setback：0 ~ 80 mm
  · Saddle angle：-15 ~ +15 °

3.6 验收标准
  · 所有选装字段留空时，界面、绘图、对比表与 V1.0 行为完全一致。
  · 填写选装字段后，车架几何结果与不填写时完全相同。
  · 模板保存、导出、导入、载入后选装字段完整保留。
  · 多车对比时，部分车填写、部分车留空的显示正确（“—”占位）。
  · 修改选装字段只触发对应显示更新，不改变原有 solve() 结果。


四、非目标（V1.1 不做）
--------------------------------------------------------------------
  · 不引入任何第三方库、构建步骤或联网依赖。
  · 不改变现有 11 项必要输入与 12 项结果的几何推导关系。
  · 不做账号体系、云同步、在线数据库。
  · 不要求把选装数据做成高精度装配图；V1.1 以数据记录与对比为主。
  · 不实现“在线导入已发布车型数据”，该功能仍保留为后续扩展点。

六、待确认问题
--------------------------------------------------------------------
1. 模板导出粒度：默认“全部模板导出”是否足够？是否需要“导出当前车/单个
   模板”？
2. 导入同名模板时，默认是覆盖、保留两者，还是每次询问？
3. “把立角度”采用哪种定义：
   a) 相对水平线的角度；
   b) 相对转向轴线的上升角（常见把立标称方式）；
   c) 直接输入上扬量（mm）。
4. “坐高”的测量方式：
   a) 五通中心沿立管方向到坐垫顶面；
   b) 五通中心到坐垫顶面的直线距离；
   c) 五通中心到坐垫顶面的垂直高度。
   三者数值会略有差异，需要在 UI 提示中明确。
5. 座管数据是否需要包含“座管露出长度 / 座管直径 / 座管后飘角”等更多字段？
6. 选装数据是否需要在画布上绘制示意（坐垫位置、把横位置、曲柄圆）？
   还是 V1.1 仅做数据记录与对比？
7. 是否需要把选装数据也纳入 Compare 的差值显示？（建议需要）

八、实现备注（2026-10-27）
--------------------------------------------------------------------
  · 模板导出/导入已实现：全部模板导出为 schemaVersion 1 的 JSON；
    导入同名模板时询问是否覆盖，取消则自动改名保留两份；旧模板可读。
  · 把立角度采用"相对舵管垂线"定义：0° = 垂直舵管伸出，正角度沿

    与 Seatpost Insert Length，负值以橙色提示。
  · Personal Fitting Area 全部字段可留空；不参与车架 solve，不影响
    Reach/Stack/Wheelbase/Trail；数据进入模板、导出和对比表。
  · 单文件 bike_geo.html 与轻量分享 zip 已重新生成；
    单元测试 53 个、浏览器交互测试全部通过。
